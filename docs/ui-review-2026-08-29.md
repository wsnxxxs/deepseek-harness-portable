**审查方式**：静态代码审查 + 对比度手算（基于 `tokens.module.css` 的内联回落调色板）+ 官方包交叉比对。**未修改任何文件。**

## 0. 结论摘要

### 0.1 总体评价

这套 UI 的**底座是健康的**：

- 设计令牌体系完整且分层合理（`--zx-*` 覆盖字阶/间距/圆角/控件高度/表面/描边/文字色/强调色/动效/字体），**严格口径令牌化率 ≈ 90%**
- 明暗双主题的派生色做了系统性重写（`tokens.module.css:164-225`），且注释说明了每一处百分比为何在浅色下要变——这是高于平均水平的设计工程
- 字体族 8/8、字号阶梯 189/189 完全落在变量上，**零逃逸**
- 已导出 9 个原子组件（`Card`/`SectionTitle`/`IconButton`/`Button`/`Pill`/`Popover`/`EmptyState`/`Spinner`/`DiffCount`）

但存在**三类系统性问题**，恰好对应你问的三个方向：

| 方向 | 核心结论 | 问题数 |
|---|---|---|
| 界面设计规范（无障碍/响应式/视觉） | 对比度有多处硬性不达标，z-index 完全无尺度且已存在实际冲突 | 86 |
| 交互逻辑统一性 | 三个模态层无一实现焦点陷阱，aria-live 播报 7 处缺口，加载态有 1 处永久死锁 | 43 |
| 与 DSH 官方 WebUI 对齐 | 上下文计量、消息级操作（复制/分支/反馈）等 WebUI 标配能力缺失 | 14 |

**总计 143 条**：🔴 关键 25 · 🟡 重要 65 · 🔵 建议 53

### 0.2 最该先修的 8 件事

1. `--zx-warning` 令牌名拼错（`SettingsSurface.module.css` 4 行）→ 状态色不随主题变，浅色下对比度掉到 2.25:1
2. `--zx-label-muted` / `--zx-label-faint` 混合百分比过低 → 时间戳、计数、分区标签等语义文字低于 4.5:1
3. light 分支漏写 `--zx-focus-ring` → 浅色主题焦点环回落为深色蓝
4. z-index 13 处裸数字，`SummaryCard` 与 `Workbench.scrim` 同为 20 → 叠放顺序退化为 DOM 顺序的真 bug
5. `useInventory` 的 `.catch(() => {})` 缺 `setLoading(false)` → 网络异常时插件面板永久转圈
6. 三个 `aria-modal="true"` 浮层无焦点陷阱与焦点归还
7. `CommandPalette` 缺 Combobox/Listbox 语义 → 屏幕阅读器无法感知键盘高亮行
8. 卡片头部 9 处实现横跨 3 种字号/3 种字重/2 种颜色/4 种高度，`ui.card` 与 `ui.sectionTitle` 零次使用

### 1.2 对比度计算前提

`--zx-*` 建立在 Host 的 `--dsw-alias-*` 之上。所有数值基于 **Host 未声明别名时的内联回落值**（即 `var(--dsw-alias-x, #fallback)` 的 fallback），采用 WCAG 2.1 相对亮度公式，按浏览器默认行为在 gamma 编码的 sRGB 通道上做 alpha 合成（`color-mix(x N%, transparent)` ≈ `rgba(x, N)`）。

> 若 Host 注入了自定义主题，实际值会漂移，但**层级关系与失败结论不变**。建议上线前用同一公式在真实 Host 主题上复核一遍。

## 2. 设计规范合规性

### 2.1 🔴 令牌名拼写错误（收益最高的一处改动）

**`settings/SettingsSurface.module.css:408 / 409 / 805 / 807`**

```css
background: var(--zx-warning, #d9a441);           /* ← 令牌名错了 */
```

全仓确认 `--zx-warning` **从未定义**，tokens 里定义的是 `--zx-warn`（`tokens.module.css:90 / 194`）。后果：

- 4 处永远走 `#d9a441` 回落，**明暗两主题都不变**
- 浅色主题下 `#d9a441` 叠在白底，对比度仅 **2.25:1**（SC 1.4.3 需 4.5:1，SC 1.4.11 非文本需 3:1，双违规）
- 正确值应是 light 的 `#9a6700`（≈5.2:1）

**修复**：把 4 行 8 处 `var(--zx-warning, #d9a441)` 改为 `var(--zx-warn)`，删除硬编码回落。

### 2.2 🔴 文字色对比度系统性偏低

#### `--zx-label-muted`（承载正文级辅助文字）

| 主题 | 定义 | bg-app | bg-panel | bg-card | bg-overlay | 判定 |
|---|---|---|---|---|---|---|
| Dark | secondary 72% | 4.80:1 ✅ | 4.67:1 ✅ | 4.54:1 ✅ | **4.43:1 ❌** | 浮层内不达标 |
| Light | secondary 82%（白底） | 3.86:1 ❌ | 4.01:1 ❌ | 4.17:1 ❌ | — | **全部不达标** |

命中位置：`shell/ui.module.css:305/311`（菜单 label/detail）、`shell/CommandPalette.module.css:125`（结果行描述）等大量浮层内文字。

> `tokens.module.css:185-186` 的注释说"light 的 muted 比 dark 抬得更高（82% vs 72%），因为向白衰减比向黑衰减更快"——**推理方向正确，但幅度不够**：light 的 secondary 基色 `#59606b`（L=0.1155）比 dark 的 `#a9aab0`（L=0.4032）暗太多。

**修复**：dark 72% → **78%**；light 82% → **90%**（或把 secondary 基色提到 `#4d545e` 后保持 82%）。建议同时新增 `--zx-label-muted-strong` 供浮层内使用。

#### `--zx-label-faint`（全局不达标）

| 主题 | 定义 | 实测 |
|---|---|---|
| Dark | secondary 48% | **2.71 ~ 2.76:1** ❌ |
| Light | secondary 60% | **2.64:1** ❌ |

两者均远低于 4.5:1，也低于 3:1 的大字门槛。而 `--zx-label-faint` 被广泛用于**承载真实语义**的内容，不是装饰：

| 用途 | 位置 |
|---|---|
| 时间戳 | `shell/LeftRail.module.css:217 .rowTime`、`:56 .shortcut` |
| 计数/统计 | `shell/Aside.module.css:145 .goalMeta`、`:236 .fileMeta`、`chat/Transcript.module.css:302 .stats`、`shell/PlanCard.module.css:165 .progress` |

**修复（推荐方案）**：令牌重命名以强制约束——

```css

--zx-label-decor: color-mix(in srgb, var(--zx-label-secondary) 48%, transparent);
/* 承载语义的第三级文字，目标 ≥4.5:1 */
--zx-label-tertiary: color-mix(in srgb, var(--zx-label-secondary) 68%, transparent);
```

然后把上表 8 处从 `faint` 迁到 `tertiary`。

### 2.3 🟡 控件边框作为唯一识别线索时不合规

`--zx-border`（11%/10%）与 `--zx-border-soft`（7%/6%）实测仅 **1.12 ~ 1.35:1**。

按 **WCAG SC 1.4.11** 需要区分两种用途：

- ✅ **装饰性分隔线豁免**——用于视觉分组的（`Workbench.module.css:35` rail 右边框、`Transcript.module.css:293 .divider::before`、`LeftRail.module.css:79 .treeDivider`）不受 3:1 约束，**无问题**
- ❌ **作为控件唯一边界时不合规**——以下是识别控件存在与范围的唯一视觉线索，需要 3:1：

```
shell/ui.module.css:117  .button              shell/TopBar.module.css:46  .chip
shell/TopBar.module.css:68 .workspaceTrigger   settings/SettingsSurface.module.css:283 .select
settings/SettingsSurface.module.css:295 .number / :308 .stepper / :441 .fieldInput / :353 .search
git/GitPanel.module.css:153 .input             shell/LeftRail.module.css:271 .workspaceInput
shell/QuestionComposer.module.css:178 .radio/.checkbox   （用 --zx-label-faint，仅 2.73:1）
settings/SettingsSurface.module.css:360 .tagMuted
```

**修复**：新增 `--zx-border-control: color-mix(in srgb, var(--zx-label-primary) 38%, transparent)`（dark 叠 bg-card ≈3.1:1）专供输入框/开关/复选框；装饰性分隔线继续用 `--zx-border-soft`。

### 2.4 🔴 light 分支漏写 `--zx-focus-ring`

`tokens.module.css:121` 定义：

```css
--zx-focus-ring: 0 0 0 2px color-mix(in srgb, var(--dsw-alias-brand-primary, #4c8dff) 55%, transparent);
```

light 块（`:164-225`）重写了 `--zx-accent`（`--dsw-alias-brand-primary, #2563eb`），但 **`--zx-focus-ring` 未重写，仍直接读裸别名**。后果：

1. Host 未声明品牌别名时，浅色主题焦点环是**深色蓝 `#4c8dff`**，与同屏 `#2563eb` 强调色不一致
2. 焦点环**绕过 `--zx-accent`**，任何对 `--zx-accent` 的用户覆盖都不会传导

这是全库唯一真正"dark 有、light 漏"的派生色。

**修复**：

```css
/* dark 基块：改为引用 --zx-accent */
--zx-focus-ring: 0 0 0 2px color-mix(in srgb, var(--zx-accent) 55%, transparent);

/* light 块补一行 */
--zx-focus-ring: 0 0 0 2px color-mix(in srgb, var(--zx-accent) 55%, transparent);
```

### 2.6 🔴 z-index 完全无尺度，且已存在实际冲突

13 处全部是裸数字，无任何 `--zx-z-*` 令牌：

| 值 | 位置 |
|---|---|
| `1` / `2` | `DiffViewer.module.css:70 / :139` |
| `2` | `Workbench.module.css:49`（rail 拖拽把手） |
| **`20`** | **`Workbench.module.css:189` `.scrim`（抽屉遮罩）** |
| **`20`** | **`SummaryCard.module.css:11`（浮层卡片）← 冲突** |
| `30` | `Workbench.module.css:216 / :238`（compact 抽屉） |
| `40` | `ui.module.css:208` `.popover` |
| `60` / `70` | `CommandPalette.module.css:6` / `DirectoryPicker.module.css:6` |
| `80` | `SettingsSurface.module.css:476`（`position: fixed`） |
| `90` | `ui.module.css:60`（tooltip） |
| **`1100`** | **`SelectMenu.module.css:58`（`position: fixed`）← 异类** |

四个问题：

1. **无统一尺度** —— 与其余 90% 令牌化的体系割裂
2. **`20` 被两个不同职责的元素共用** —— `Workbench.scrim` 与 `SummaryCard.card`。二者都在 `.root` 的 `isolation: isolate` 上下文中，叠放顺序**退化为 DOM 顺序**。若 SummaryCard 在 DOM 中先于 scrim，环境摘要卡会被自己的遮罩盖住
3. **`1100` 是异类** —— 量级明显来自 Host/DSH 体系（下拉菜单常用 1000+），混进本包 1~90 尺度后 SelectMenu 会盖住未来任何新增模态层
4. **定位上下文不统一** —— `SettingsSurface.dialogBackdrop` 与 `SelectMenu.menu` 用 `position: fixed`，脱离了 Workbench 的 `isolation: isolate`（`Workbench.module.css:22`），实际进入 body 级层叠上下文，与包内 60/70/90 不再可比

**修复**：在 `tokens.module.css` 新增尺度：

```css
--zx-z-base: 0;      --zx-z-sticky: 10;   --zx-z-scrim: 20;
--zx-z-drawer: 30;   --zx-z-popover: 40;  --zx-z-modal: 60;
--zx-z-dialog: 80;   --zx-z-menu: 90;     --zx-z-tooltip: 100;
```

配套：`SummaryCard.card` 的 `20` → `var(--zx-z-popover)`；`SelectMenu` 的 `1100` → `var(--zx-z-menu)`；`SettingsSurface.dialogBackdrop` 的 `fixed` 改 `absolute` 挂回 Workbench 根下（若必须 fixed，则保证根上没有更高的 isolate 边界）。

### 3.1 🔴 三个模态层无一实现焦点管理

| 浮层 | 初始焦点 | 焦点陷阱 | 焦点归还 |
|---|---|---|---|
| `CommandPalette.tsx:301-357` | ✅ 聚焦搜索框（`:84`） | ❌ | ❌ |
| `DirectoryPicker.tsx:88-149` | ❌ **完全没有** | ❌ | ❌ |
| `SettingsSurface.tsx:976-1027` | ⚠️ 仅 copy 分支有 `autoFocus`（`:988`） | ❌ | ❌ |

后果：`DirectoryPicker` 打开后焦点仍在背景按钮上，键盘用户 Tab 会走进已被遮罩盖住的底层控件；`CommandPalette` 关闭后焦点落到 `<body>`。

违反 **WCAG SC 2.4.3 Focus Order**；**WAI-ARIA APG Dialog (Modal)** 模式。

**修复**：抽出统一 hook，一次性覆盖三者：

```ts
function useModalFocus(open: boolean, panelRef: RefObject<HTMLElement | null>) {
  useEffect(() => {
    if (!open) return
    const previous = document.activeElement as HTMLElement | null
    panelRef.current?.querySelector<HTMLElement>('button, input, textarea, [tabindex]:not([tabindex="-1"])')?.focus()
    const onKeyDown = (e: KeyboardEvent) => {
      if (e.key !== 'Tab' || panelRef.current === null) return
      const items = [...panelRef.current.querySelectorAll<HTMLElement>('button, input, textarea, [tabindex]:not([tabindex="-1"])')]
        .filter(el => !el.hasAttribute('disabled'))
      if (items.length === 0) return
      const first = items[0], last = items[items.length - 1]
      if (e.shiftKey && document.activeElement === first) { e.preventDefault(); last.focus() }
      else if (!e.shiftKey && document.activeElement === last) { e.preventDefault(); first.focus() }
    }
    document.addEventListener('keydown', onKeyDown)
    return () => { document.removeEventListener('keydown', onKeyDown); previous?.focus() }
  }, [open, panelRef])
}
```

行为基准参照 `settings/SelectMenu.tsx:72-76, 99-103`——它是全项目唯一正确归还焦点的实现。
