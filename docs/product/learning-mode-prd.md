# PRD：学习模式 2.0——从会话教学到可持续掌握

状态：提案  
版本：v0.1  
日期：2026-08-26  
产品：DeepSeek Harness Portable / Interactive Learning preset  
产品负责人：待定

## 1. 产品摘要

学习模式当前已经具备较强的教学内核：能够识别学习意图，按学习者证据调整教学动作，在需要时使用原生交互视觉，并在 session 内保存可恢复的学习状态。

本 PRD 不要求重做教学内核，而是把已有能力产品化为一条用户看得懂、用得上、愿意回来复习的路径：

> 进入学习模式 → 明确想学什么 → 每轮只推进一步 → 看见学习证据 → 保存成果 → 在未来复习并迁移。

90 天目标是补齐三个缺口：

1. **可发现：** 用户能在第一次看到产品时理解学习模式，并在一个动作内开始。
2. **可看见：** 用户能看见当前目标、已展示的证据、尚未验证的部分和下一步。
3. **可复习：** 用户能主动保存学习成果，在之后以轻量方式重新回忆，并把结果带回教学对话。

## 2. 背景与机会

通用 AI 产品正在把“学习模式”变成标配。ChatGPT Study Mode、Gemini Guided Learning、Perplexity Learn Mode 都强调分步解释、引导问题和知识检查；NotebookLM、Quizlet 强在材料和复习；Khanmigo 强在课程内容、教育信任和机构治理。

本项目的差异不在“也会提问”，而在于：

- 视觉不是生成图片，而是可操作、可访问、语义明确的原生组件。
- 学习状态是基于证据的暂定判断，不会轻易把一次点击或一句自评算成掌握。
- 学习过程是普通对话中的非阻塞增强，不会把每一轮变成 Continue/Reveal 仪式。
- 学习状态可随刷新、恢复、消息压缩和分叉继续。

目前这些差异主要存在于内部行为和文档中，用户不一定能看见，因此需要一层产品体验把它们显性化。

## 3. 用户问题

### 3.1 用户看不懂入口

用户看到“学习模式”时，通常只知道它可能会更像老师，不知道：

- 什么时候会问问题；
- 为什么有时直接讲，有时先校准；
- 视觉什么时候出现；
- 是否会影响普通的编码和工作任务；
- 是否可以随时退出。

### 3.2 用户看不见学习成果

模型内部可以区分目标、缺口、部分正确、失败教学动作和迁移，但用户看到的仍然是连续对话。用户很难回答：

- 我现在到底学会了什么？
- 哪一点只是听懂但还没有独立做过？
- 下一步应该继续、复习，还是换一种解释？

### 3.3 用户学完没有回来理由

当前状态主要服务当前 session。没有用户主动保存的主题学习档案、复习日期、稳定的卡组或“上次卡在哪里”的入口。一次很好的对话很可能在关闭窗口后失去长期价值。

### 3.4 材料学习与实时辅导断开

用户有讲义、PDF、代码文件或链接时，需要一个清晰的路径把材料变成章节结构、来源锚点、理解问题和复习内容，而不是只得到一次摘要。

## 4. 目标与非目标

### 4.1 产品目标

1. 提升学习模式从“看到入口”到“完成第一轮有效学习”的转化。
2. 提高一次学习片段中产生解释、预测、对比或新情境应用的比例。
3. 让用户在片段结束时能带走一份可理解、可纠正的学习成果。
4. 建立用户主动选择的轻量复习闭环。
5. 保持普通对话默认、非阻塞交互、学术诚信和可纠正状态等核心原则。

### 4.2 非目标

- 90 天内不做完整课程平台、知识图谱或 LMS。
- 不做全局、隐式的“学习风格”人格画像。
- 不把每次学习都强制变成测验或固定课程。
- 不承诺考试分数、长期掌握度或“替代老师”。
- 不做任意可执行 widget、静默采集滑块状态或复杂游戏化。
- 不把 K-12 学校治理、家长控制和教师后台作为首发范围。

## 5. 目标用户与场景

### Persona A：技术型自学者

目标：理解算法、代码执行、系统机制、数学或数据概念。  
痛点：知道术语但无法解释；看懂一个例子，遇到变式就卡住。  
期望：结构图、代码轨迹、公式推导、一个有针对性的练习。

### Persona B：工作中的快速学习者

目标：在面试、汇报、项目切换前快速补齐知识。  
痛点：时间有限，不想从完整课程开始，但也不想只背一段答案。  
期望：先直接解决当前阻塞，再用一个最小练习确认是否能讲清楚。

### Persona C：材料驱动学习者

目标：从讲义、PDF、Markdown、代码文件或链接学习。  
痛点：资料多、重点不清楚，摘要看完仍不知道自己是否能应用。  
期望：来源锚点、章节 map、按自身缺口解释、复习卡。

## 6. 产品原则

1. **帮助用户做出下一步，而不是只生成更多内容。**
2. **先给足够支架，再要求一次有意义的主动回忆。**
3. **视觉服务于一个关系或动作，不为展示功能而展示。**
4. **证据优先于自信；“未验证”是合法状态。**
5. **学习模式随时可退出，不破坏普通工作流。**
6. **长期保存必须由用户主动选择，且可以纠正和删除。**
7. **所有营销承诺都以真实用户行为证据为基础。**

## 7. 范围与优先级

### P0：首发必须做

#### P0-1 学习启动卡

**目标：** 降低第一次进入学习模式的理解和操作成本。

用户在新会话、模式选择或普通对话中看到学习模式时，展示：

- 名称：学习模式
- 一句话：专注理解，不代做
- 三个承诺：需要时画图、每轮只推进一步、随时可切回普通对话
- 四个快捷入口：
  - 理解一个概念
  - 从材料开始
  - 解决卡点但想学会
  - 做一次回忆练习
- 一个 30 秒示例或“看看它如何工作”入口

**需求：**

1. 用户从启动卡到第一条学习消息最多需要一次确认。
2. 用户可以直接输入自然语言，不必填写课程、年级或学习风格问卷。
3. 普通对话与学习模式状态必须有清晰视觉差异。
4. 进入学习模式后，输入框仍然是同一个正常输入框。
5. 用户可以在当前会话中一键切回普通对话，切回后不删除已有学习记录。

**验收：**

- 新用户能用一句话说清“学习模式和普通问答的差别”。
- 不提供模型、协议、preset、renderer 等工程术语作为入口文案。
- 学习模式不能因为用户提出代码实现或排障任务而强行接管。

#### P0-2 学习进度与成果卡

**目标：** 将内部学习状态转成用户可理解的反馈。

在学习片段进行中，展示轻量进度条或可展开的学习进度面板：

- 当前目标
- 当前环节：定位、讲解、练习、纠正、迁移或完成
- 已出现的证据：例如“你能解释 A 如何导致 B”
- 尚未验证的部分
- 当前建议：继续深挖、换种讲法、做一次回忆或结束

片段结束时展示成果卡：

- 本次学习目标
- 关键概念不超过 3 条
- 用户真实完成的认知动作
- 仍需练习的一个缺口
- 可选动作：保存复习、继续深挖、换个例子、导出/复制摘要、结束

**规则：**

1. 默认不显示 0–100 分。
2. “已理解”必须使用解释、预测、对比、尝试或新情境应用等可观察语言。
3. “未验证”不等于“不会”，只是没有足够证据。
4. 用户可以修改目标和系统对当前状态的判断。
5. 结束片段后不自动追加问题。

**验收：**

- 用户能在 10 秒内回答“我学到了什么、还差什么”。
- 用户点击结束后，系统不会继续追问或强迫进入下一轮。
- 刷新和恢复后，成果卡内容与会话记录一致。

#### P0-3 语义视觉引导

**目标：** 让现有原生视觉成为教学动作，而不是随机插图。

**需求：**

1. 视觉标题使用学习动作语言，例如“先预测：参数变大时曲线会怎样”。
2. 视觉前说明一句“为什么现在展示它”。
3. 视觉只承载一个关系或一个探索动作，解释文字留在对话中。
4. 参数图、代码轨迹、公式步骤等组件提供明确的“观察点”。
5. 用户完成视觉操作后，可点击“把我的观察带入回答”，把观察作为普通输入草稿带回对话。
6. 无 rich client、渲染失败或用户跳过时，必须有自洽文字降级。
7. 视觉不能把本地交互默认记成正确、掌握或迁移证据。

**验收：**

- 用户不看内部协议名称也能理解这个视觉要做什么。
- 同一轮不会同时出现视觉和强制检查点。
- 视觉失败不会阻塞消息发送或造成空白卡片。

### P1：首发后 4–8 周

#### P1-1 材料学习工作流

**目标：** 对齐 NotebookLM/Quizlet 的材料入口，同时保留本项目的实时辅导优势。

**用户流：**

1. 用户拖入 PDF、Markdown、讲义、代码文件或 URL。
2. 系统列出来源和章节/页码/标题锚点。
3. 系统生成可折叠 study map，用户选择一个要先理解的概念。
4. 学习模式引用来源解释，并在适合时提供视觉、检查点或平行例子。
5. 结束后可生成带来源锚点的复习卡和一段“我还没验证的内容”。

**验收：**

- 每一个来源驱动的关键解释都能回到原材料锚点，不能把模型补写的内容伪装成原文。
- 用户可以只选部分来源继续学习。
- 材料分析失败时仍能回到普通对话，而不是卡在导入页。

#### P1-2 用户主动保存的复习卡

**目标：** 让一次学习对话产生未来复习价值。

**需求：**

- 成果卡提供“保存为复习”。
- 默认生成 3–8 张卡，优先覆盖误解、关键区别和迁移，而不是把整段摘要拆成卡片。
- 卡片正面要求回忆、解释或预测；背面提供提示、答案、来源和原学习片段。
- 用户可以编辑、删除和重新生成卡片。
- 支持明天、3 天后、7 天后等简单的复习选项。
- 复习结果显式回传到主题学习状态；不静默扩大为全局用户画像。

**验收：**

- 用户不点击保存时，不生成长期复习对象。
- 复习卡可以在新的 session 打开。
- 复习失败能触发换一种解释或新例子，不只是显示红色分数。

#### P1-3 可纠正学习证据

**目标：** 把“可审计状态”变成信任体验。

显示示例：

> 暂时判断：你已经能解释 A 和 B 的区别；C 还没有在新例子中验证。  
> [修改判断] [用新例子试试]

用户可纠正目标、先验、缺口、证据和“是否继续提问”。纠正后要立即影响下一步，不要求用户重复整个学习过程。

### P2：形成传播与生态

#### P2-1 可分享学习片段

- 选择一个视觉、用户自己的解释和学习成果摘要。
- 默认脱敏，不导出完整 session identity、隐性状态和私人材料。
- 生成“用这个问题开始学习”的入口。

#### P2-2 主题工作区

- 用户主动创建一个主题，例如“概率基础”或“操作系统”。
- 在主题内保存来源、学习片段、复习卡和未验证清单。
- 仍然不做全局人格画像；主题数据可单独删除和导出。

#### P2-3 团队/教师能力

只有在个人学习闭环验证后再评估班级、标准、家长控制、作业与管理员报告。

## 8. 关键用户流程

### 8.1 概念学习

新会话 → 选择学习模式 → 输入“我想理解 X” → 系统根据目标和先验选择校准或直接给最小概念 → 一个例子/对比/原生视觉 → 用户解释或预测 → 系统指出具体证据和缺口 → 新情境应用 → 成果卡 → 保存复习或结束。

### 8.2 有时间压力的卡点

用户说明“十分钟后要汇报” → 先给可行动的直接帮助 → 把关键概念压缩成一个最小模型 → 询问一个不拖延的验证问题 → 提供可带走的 3 条要点 → 允许结束，不强迫深挖。

### 8.3 材料学习

上传材料 → 选择来源 → study map → 选一个章节/概念 → 有来源的解释 → 一个针对缺口的视觉或问题 → 用户应用 → 来源锚点成果卡 → 保存复习。

### 8.4 普通任务切换

学习片段中用户输入“帮我直接改这个文件/修这个 bug” → 识别为普通任务 → 清晰提示已切换 → 不注入学习工具 → 完成普通任务 → 用户再次明确学习时重新打开学习片段。

## 9. 文案建议

### 入口

- 学习模式
- 专注理解，不代做
- 需要时画图，必要时提问
- 想看答案、学会方法，还是做一次回忆？

### 进度

- 学习目标
- 你刚才展示了什么
- 还没有验证什么
- 当前建议
- 这不是分数，是根据你刚才回答整理的学习证据

### 完成

- 这段学习完成了
- 你已经能解释……
- 还可以在新例子中试试……
- 保存为 5 分钟复习
- 换种讲法
- 结束本片段

### 视觉

- 先预测，再拖动参数
- 只看一个关系
- 把我的观察带入回答
- 看不清或不想操作？继续用文字

## 10. 指标与目标

先在 P0 上线前建立两周基线，再锁定数字。建议北极星指标为：

### Qualified Learning Loop（合格学习闭环）

一个学习 session 同时满足：

1. 用户提出明确的学习目标或概念问题；
2. 系统完成至少一次有效教学动作；
3. 用户完成一次解释、预测、对比、尝试或迁移；
4. 系统给出可理解的下一步或成果卡。

这个指标比消息数、平均停留时间和生成内容长度更接近真实价值。

### 90 天候选目标

| 指标 | 候选目标 | 备注 |
|---|---:|---|
| 学习入口点击到首轮有效教学完成率 | 相对基线 +30% | 先验证入口和 onboarding |
| 合格学习闭环率 | 相对基线 +20% | 以真实用户 session 抽样复核 |
| 成果卡打开率 | ≥ 60% | 不代表学习成功，只代表可见性 |
| 用户主动保存复习率 | ≥ 20% | 只对明确长期意图的用户统计 |
| 次日复习完成率 | ≥ 35% | 需要 P1 上线后统计 |
| 用户报告的重复教学动作 | ≤ 10% | 按 session 抽样和反馈结合 |
| 无效/失败视觉降级率 | ≤ 5% | 失败时必须仍可完成对话 |
| graded 场景答案泄露 | 0 容忍 | 作为质量门槛而非均值指标 |

### 体验问题监控

- 学习模式退出和切回普通对话的原因。
- 检查点跳过、取消、超时和渲染失败。
- 用户纠正学习目标和状态的频率。
- 视觉帮助度、来源准确度和事实错误反馈。
- 用户是否能在访谈中复述“学到了什么”和“还差什么”。

## 11. 数据与隐私

1. session-local 仍是默认，不因为新增复习功能自动变成全局画像。
2. 跨 session 只保存用户主动创建的主题、卡片和复习安排。
3. “系统暂时判断”必须可修改、可删除，并标明它是证据推断而不是测量真值。
4. 视觉滑块、探针和本地探索默认不作为正确性证据；只有用户显式带回对话才参与教学。
5. 分享功能默认脱敏，不导出完整材料、身份和内部状态。
6. 当前主题和争议主题要区分来源事实、模型解释和用户推断。

## 12. 发布计划

### 阶段 0：基线与文案（第 1 周）

- 补充学习入口、首轮完成、学习闭环、视觉降级、成果卡等事件。
- 对现有用户流程做 5–8 人快速可用性访谈或内部走查。
- 完成启动卡、进度卡和成果卡的文案与信息架构。

### 阶段 1：P0（第 2–4 周）

- 上线学习启动卡。
- 上线学习进度与成果卡。
- 完成视觉标题、预测动作和“带入我的观察”。
- 继续保留旧 session 回放和普通对话路径。

### 阶段 2：P1（第 5–8 周）

- 上线材料学习入口和来源锚点。
- 上线用户主动保存的复习卡与简单间隔选项。
- 上线可纠正学习证据。

### 阶段 3：验证与传播（第 9–12 周）

- 通过对照 demo、真实 session 抽样和定性访谈验证核心卖点。
- 选择开发者和知识型自学者做小范围公开试用。
- 发布脱敏学习片段模板和复盘文章。

## 13. 风险与处理

| 风险 | 可能后果 | 处理 |
|---|---|---|
| 入口更复杂 | 用户仍不启动 | P0 只保留一个入口卡和四个明确目标，不做问卷 |
| 学习模式太爱提问 | 用户认为被考试 | 一轮最多一个关键问题；用户可直接要求完整讲解或停止提问 |
| 视觉成为装饰 | 用户觉得花哨但没帮助 | 每个视觉必须绑定一个关系和一个动作，发布前做样例评审 |
| 过度显示“掌握度” | 错误信任、教育风险 | 只显示证据和未验证状态，支持纠正 |
| 复习功能变成负担 | 用户被提醒骚扰 | 只主动保存，默认少量、可暂停、可删除 |
| 材料引用错误 | 学术和事实风险 | 显示来源锚点，区分原文和模型解释，失败时回退普通对话 |
| 竞品快速跟进 | 差异消失 | 聚焦技术学习、原生语义视觉、可恢复证据和非阻塞体验 |
| 对效果过度宣传 | 用户失望、信任下降 | 先做基线和案例，未经验证不说“提升成绩/保证掌握” |

## 14. 验收清单

### P0 必须满足

- [ ] 用户从新会话能理解学习模式的差别和退出方式。
- [ ] 用户无需填写学习风格问卷即可开始。
- [ ] 学习模式不会接管明确的普通编码、排障或查询任务。
- [ ] 每轮最多一个聚焦问题，且问题有明确教学目的。
- [ ] 视觉出现时能解释为何出现；视觉失败时普通文字仍然完整。
- [ ] 用户能看到目标、证据、缺口和下一步。
- [ ] 结束片段后不自动追加问题。
- [ ] 刷新、恢复和分叉不破坏已有学习结果。
- [ ] 用户可以纠正学习状态，不必重开 session。
- [ ] 不在 UI 或宣传中把一次提交、滑块操作或用户自评直接叫作掌握。

### P1 必须满足

- [ ] 材料来源、章节/页码锚点可见。
- [ ] 用户可主动保存、编辑、删除复习卡。
- [ ] 复习结果能回到同一主题的教学路线。
- [ ] 跨 session 保存的是用户选择的主题对象，不是隐性全局画像。
