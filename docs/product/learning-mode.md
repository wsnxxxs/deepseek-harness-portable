# 学习模式：当前行为与产品边界

> 状态：当前实现说明
> 更新：2026-09-02

本文是学习模式的产品事实源。用户界面和学习流程发生变化时先更新这里；包的接入方式见 [`apps/interactive-learning/README.zh.md`](../../apps/interactive-learning/README.zh.md)，协议字段和工具 schema 以源码为准。

## 一句话

学习模式帮助用户把概念讲清并真正用起来。普通对话仍是默认；学习模式不会接管明确的动手任务，例如编码和排障，也包括编辑或自动化。

## 入口与信息架构

- 新会话可显式选择“学习模式”。快速开始只提供三个方向：**理解一个概念**和**解决一个疑惑**，以及**学习一份材料**。点击后只把提示词模板放入输入框，不预填具体主题；“学习一份材料”的模板以 `@` 结尾，直接把附材料这一步交到用户手上。
- 对话内保留 **对话 / 轨迹 / 学习过程**。学习模式页只提供开始入口和当前学习会话，不另外建立资料浏览页面。
- 学习模式支持三种开始方式：**理解一个概念**、**解决一个疑惑**、**学习一份材料**。材料在当前学习会话中通过 `@` 附加和使用。
- 学习界面沿用项目既有的深色主题、圆角、间距、焦点环和选中态；相同动作使用相同的按钮和状态表达。控件形状按场景固定：对话流内的行内动作用胶囊，表单与对话框按钮用 8px 圆角。

## 教学行为

1. 首轮先判断用户是在建立理解，还是在完成普通任务；普通任务沿用普通对话路径。判定偏向学习：只有“写 / 改 / 修”这类明确的动手指令才算普通任务，“解释这段代码”“教我实现一个队列”都是学习请求。判成普通任务时只收回学习工具，教学策略仍在，所以判错也不会让这一轮失去教学能力。
2. 学习片段开始后，简短回答、继续困惑和追问继承当前上下文。用户明确换任务、重置或结束后才退出该片段。
3. 先给完成理解所需的最小解释。只有交互确实能改变理解时才出现语义图示或理解检查，且都不阻塞普通输入。
4. 检查点只在回答会改变下一步教学时使用，不做每轮固定的“继续 / 揭示”仪式。图示不可用时，正文仍须独立成立。每轮的教学路线由 Host 判定并随该轮下发，模型不再自行重新分类。
5. 学习结束不自动追加无意义的问题；用户可以继续深挖或换一种讲法，也可以尝试新例子或结束。

## 状态与长期内容

- `LearnerState` 只属于当前 session，记录目标、先验、缺口、误解、证据、阶段和下一步。它是可修正的教学假设，不是跨会话画像、人格标签或“学习风格”。
- 只有用户实际解释、预测、对比、尝试或迁移产生的证据才推进状态；一次提交、自评或“我懂了”不会自动等同于掌握。
- 用户通过 `@` 附上的材料由 Host 在当前学习会话中准备，模型只通过受限的只读能力读取材料。材料检索默认由 `LearnerState` 推导；用户点名要看哪一段时，用户的原话直接作为检索依据，状态为空也能检索。
- 学习状态服务于当前会话的教学推进，不自动建立独立的资料库或跨会话画像。概念卡相关动作只在学习对话中按证据和用户确认规则处理。
- 材料重新解析后，失效的章节/页码锚点要明确标记；不能把不再可靠的引用继续显示成可靠证据。

## 当前支持范围

- 材料：PDF、Markdown、纯文本、常见代码文本、DOCX 和 PPTX。扫描页、复杂版式或缺少可选解析依赖时允许降级，并显示无法读取的范围。
- 学习视觉：按语义选择关系图、流程/时序、公式步骤、数据表、代码轨迹、材料导览和回忆卡等原生组件。视觉是可选增强，不替代文字回答。函数曲线和标量/向量场里的数学表达式用普通中缀写法（`sigmoid(w*x + b)`），由 Host 在工具边界解析；参数 id 只能用字母、数字和下划线，因为表达式里的 `-` 一律是减号。
- 学习模式保存当前会话所需的材料索引和学习状态，以便继续完成本次学习；用户界面不提供独立的资料库、学习库或复习入口。
- 模式边界：模型没有文件写入工具；材料摄入、学习状态和确认后的概念卡写入由 Host 按确定路径处理。

## 明确不做

- 每轮强制问答、固定课程脚本或把所有回答变成卡片。
- 自动建立隐式的跨会话掌握画像或知识图谱。
- 任意可执行 widget、模型驱动的工程文件修改，以及静默写入用户文件。
- 用一次提交、滑块操作或自评直接宣称“已掌握”。

## 维护规则

- 产品行为变更先更新本文，再同步包 README 中必要的用户可见部分。
- 工具 schema、事件字段、渲染器清单和测试命令不在本文复制；它们以类型声明、实现和 package scripts 为准。
- 竞品研究只保留能影响当前决策的结论：入口要明确、会话内过程与长期内容要分层、引用要可追溯、增强交互不能阻塞主对话。
- 尚未实现的设想写入 issue 或 roadmap，不要混在“当前支持范围”里。
