# 学习模式：当前行为与产品边界

> 状态：当前实现说明
> 更新：2026-08-28

本文是学习模式的产品事实源。用户界面和学习流程发生变化时先更新这里；包的接入方式见 [`apps/interactive-learning/README.zh.md`](../../apps/interactive-learning/README.zh.md)，协议字段和工具 schema 以源码为准。

## 一句话

学习模式帮助用户把概念讲清并真正用起来。普通对话仍是默认，学习模式不会接管明确的编码、排障、编辑或自动化任务。

## 入口与信息架构

- 新会话可显式选择“学习模式”。快速开始只提供三个方向：**理解一个概念**、**解决一个疑惑**、**学习一份材料**。点击后只把提示词模板放入输入框，不预填具体主题。
- 对话内保留 **对话 / 轨迹 / 笔记**。笔记只记录当前会话的学习目标、证据、路线和结果；需要长期保留时，用户再执行“保存到学习库”。
- 侧边栏的 **学习库** 是长期资料入口，按 **材料 / 已保存 / 概念卡 / 复习** 分层。它与当前会话笔记职责不同，也不是另一套对话记录。
- 学习库页面以材料为主：添加材料、查看最近阅读、查看解析状态；解析器、字数和文件大小等技术信息放在详情中。
- 学习界面沿用项目既有的深色主题、圆角、间距、焦点环和选中态；相同动作使用相同的按钮和状态表达。

## 教学行为

1. 首轮先判断用户是在建立理解，还是在完成普通任务；普通任务沿用普通对话路径。
2. 学习片段开始后，简短回答、继续困惑和追问继承当前上下文。用户明确换任务、重置或结束后才退出该片段。
3. 先给完成理解所需的最小解释。只有交互确实能改变理解时才出现语义图示或理解检查，且都不阻塞普通输入。
4. 检查点只在回答会改变下一步教学时使用，不做每轮固定的“继续 / 揭示”仪式。图示不可用时，正文仍须独立成立。
5. 学习结束不自动追加无意义的问题；用户可以继续深挖、换一种讲法、尝试新例子或结束。

## 状态与长期内容

- `LearnerState` 只属于当前 session，记录目标、先验、缺口、误解、证据、阶段和下一步。它是可修正的教学假设，不是跨会话画像、人格标签或“学习风格”。
- 只有用户实际解释、预测、对比、尝试或迁移产生的证据才推进状态；一次提交、自评或“我懂了”不会自动等同于掌握。
- 用户通过 `@` 附上的材料在当前工作区建立或更新学习库。原件、提取文本和章节结构都由 Host 写入学习库，模型只通过受限的只读能力读取材料。
- 当前会话笔记不会自动变成长期知识。用户明确保存的回答或笔记进入“已保存”；独立迁移后才可以提出概念卡建议，只有用户确认才进入概念卡和复习队列。
- 材料重新解析后，失效的章节/页码锚点要明确标记；不能把不再可靠的引用继续显示成可靠证据。

## 当前支持范围

- 材料：PDF、Markdown、纯文本、常见代码文本、DOCX 和 PPTX。扫描页、复杂版式或缺少可选解析依赖时允许降级，并显示无法读取的范围。
- 学习视觉：按语义选择关系图、流程/时序、公式步骤、数据表、代码轨迹、材料导览和回忆卡等原生组件。视觉是可选增强，不替代文字回答。
- 学习库：材料、已保存笔记、用户确认的概念卡和到期复习；内容保存在用户自己的工作区，便于查看、编辑、导出和删除。
- 模式边界：模型没有文件写入工具；材料摄入、笔记落盘和确认后的概念卡写入由 Host 按确定路径处理。

## 明确不做

- 每轮强制问答、固定课程脚本或把所有回答变成卡片。
- 自动建立隐式的跨会话掌握画像或知识图谱。
- 任意可执行 widget、模型驱动的工程文件修改，以及静默写入用户文件。
- 用一次提交、滑块操作或自评直接宣称“已掌握”。

## 维护规则

- 产品行为变更先更新本文，再同步包 README 中必要的用户可见部分。
- 工具 schema、事件字段、渲染器清单和测试命令不在本文复制；它们以类型声明、实现和 package scripts 为准。
- 竞品研究只保留能影响当前决策的结论：入口要明确、会话内过程与长期内容要分层、引用要可追溯、增强交互不能阻塞主对话。
- 尚未实现的设想写入 issue 或 roadmap，不要混在“当前支持范围”里。
